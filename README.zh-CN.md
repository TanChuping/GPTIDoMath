# GPTIDoMath

**让一条 ChatGPT Pro 消息干上好几个小时。** 你发给网页版 ChatGPT Pro 一段读起来像长篇数学研究会话开头的「开场」，真正的任务放在一份它先读的文件里。几个小工具让活一直干下去：70 分钟先交一份保底成品，之后分阶段存档；不花消息次数就能中途改要求；网页那边可以请你的电脑代跑；活交上来时你的 agent 会被叫醒。

> [!WARNING]
> **实验性做法。** 在一个小圈子里实测，它确实让网页版 Pro 的长任务明显更稳、跑得更久，但不保证 100% 稳定：断连仍会发生，方法也可能随时失效。使用前请先读[免责声明](#免责声明)。

## 从这里开始（后面的可以不读）

1. 你需要一个**能跑命令的编程 agent**（Claude Code、Codex 或类似的），以及 **ChatGPT Pro** 订阅。
2. 把技能目录 `skills/gptidomath` 装到你的 agent 读技能的地方：
   ```sh
   git clone https://github.com/TanChuping/GPTIDoMath
   # Claude Code
   mkdir -p ~/.claude/skills && cp -r GPTIDoMath/skills/gptidomath ~/.claude/skills/
   # Codex
   mkdir -p ~/.codex/skills && cp -r GPTIDoMath/skills/gptidomath ~/.codex/skills/
   ```
   用 [skills CLI](https://github.com/vercel-labs/skills) 的话：`npx skills add TanChuping/GPTIDoMath`。别的 agent：让它去读 `skills/gptidomath/SKILL.md`。
3. 对你的 agent 说：**「帮我配好 GPTIDoMath。」** 它会问你几个问题（谁来发消息、用不用 Google Drive、用什么语言），把每个选项的好处和代价讲清楚，装好并测试你选的东西，再跑一个小试验。
4. 以后就说：**「用 GPTIDoMath 把这件事发给 ChatGPT Pro：……」**，再讲清要干什么。

## 里面有什么

| 部分 | 干什么 |
|---|---|
| **数学开场**（[`openers/`](skills/gptidomath/openers/)） | 四份示例开场（谱理论、有向拓扑、统计物理、逻辑与重写），外加续篇和重启开场，中英文各一套，配好每种发送路线的结尾。读起来是一个大而难、很有价值的研究问题，却不含任何任务内容。建议你照着写一份自己的。 |
| **题面骨架**（[`task/`](skills/gptidomath/task/)） | 真正的提示词：要做什么、完整工作清单、子代理分工、70 分钟时间安排、交付格式；走 Drive 时还教它怎么接中途改动、怎么请你本机代跑。开头一小段告诉模型：开场只是一种叙述方式，以本文件为准。 |
| **仓库镜像** | 一条命令把最新提交推到 Google Drive（或打成一个能直接上传的压缩包），附文件表和函数表，自动打码认得出的私密信息。 |
| **插话通道** | 任务跑着的时候写一个文件就能追加或修改要求。不发新消息，不多花次数。 |
| **代跑请求** | 网页那边可以请你的电脑代跑它沙箱里跑不了的东西（显卡、真机、你的系统），等结果的同时接着干活。 |
| **守候器** | 出现 `DONE.txt` 或新的阶段包，或者 35 分钟没有任何新文件时，叫醒你的 agent。 |
| **Pro 记账** | 每发一条 Pro 消息记一笔，因为 ChatGPT 不显示还剩几次。 |
| **Drive 授权卡自动点击** | ChatGPT 弹出 Google Drive 授权卡时，随机等几秒后点「始终允许」。 |

全部都是带说明书的参考实现，只在一种环境里测过（Windows 11 + Google Drive 电脑版 + Python 3.12）。你的 agent 会按你的系统改编；每份说明书都先讲原理，方便它改。

## 选路线

配置时 agent 会问你这个。要选两样：**谁来发**、**材料怎么送过去**。

| 谁来发 | 你要准备 | 好处 | 代价 |
|---|---|---|---|
| **你自己手发** | 不用额外准备 | 简单，一切看得见 | 发消息和点 Drive 授权卡时你得在电脑前；任务跑着时要让你的 agent 开着，否则没人插话、没人回它的代跑请求 |
| **[Voyager CLI](https://github.com/voyager-crew/voyager-cli)**（独立的开源工具） | Node.js、Voyager CLI、Voyager 浏览器插件，并完成配对 | 在终端里全自动；能同时跑几单 | 要装、要维护一个第三方工具 |
| **你的 agent 用浏览器代发** | 给 agent 装浏览器控制插件（例如 Claude in Chrome，或 Codex 的浏览器插件） | 实测最多；ChatGPT 页面改版时 agent 能自己找路 | 花掉 agent 的一些 token；它在你登录着的浏览器里操作 |

| 材料 | 你要准备 | 好处 | 代价 |
|---|---|---|---|
| **Google Drive**（推荐） | ChatGPT 连上 Google Drive，本机装 Google Drive 电脑版（或 rclone） | 传一次，每个对话都能用；插话、代跑、叫醒全部可用 | 要配置一次；每个新对话第一次写 Drive 时会弹授权卡 |
| **上传压缩包** | 不用准备 | 最简单 | 没有插话、代跑和叫醒；每次追问都要重新上传 |
| **GitHub 仓库** | ChatGPT 的 GitHub 应用 | 任务受版本管理 | **作者没有实测过。** 交付和插话的脚本要你自己做 |

**Drive 授权卡。** 每个新对话第一次往 Drive 写东西时，ChatGPT 会停在「允许 ChatGPT 使用 Google Drive 吗？」，没人点就一直卡着。可选的办法：
- [GPT Voyager](https://chromewebstore.google.com/detail/gpt-voyager/ofhnmgjaffpdldimjdenjoneocicolfi) 插件（[源码](https://github.com/TanChuping/chatgpt-voyager)）里有一个需要手动开启的自动允许设置；
- Voyager CLI 有 `--approve-apps always`；
- 本仓库带了一个小插件和一段控制台脚本；
- 也可以手点。

这些都不保证一直有效，所以发消息的人发完约 5 分钟要回去看一眼。

**各种组合能用什么。** 插话、代跑和叫醒取决于材料怎么送，和谁来发无关。走 Drive 三样都能用，前提是任务跑着时你的 agent 一直开着；上传压缩包则三样都用不了。

## 和「网页版反代」「给电脑挂 MCP」那类项目有什么不同

常和本项目一起被提到的还有两类项目：一类把 ChatGPT 网页版反向代理成非官方 API，一类用 MCP 把 ChatGPT 接到你电脑上的工具。GPTIDoMath 两样都不是。

| | 网页版反代 | 给电脑挂 MCP | GPTIDoMath |
|---|---|---|---|
| **怎么用 ChatGPT** | 从网页版取出会话 Cookie 或令牌，当成非官方 API 重放，常常还要经过别人的服务器 | 正常的网页版，外加一个把你电脑上的工具暴露出去的连接器或隧道 | 正常的网页版，像一个人那样使用，外加 ChatGPT 自带的 Google Drive 连接器 |
| **额度** | 常被用来换取订阅本不包含的类 API 用法，或几个人合用 | 正常 | 正常：每条消息都照常从你自己的 Pro 额度里扣，我们只是让每条消息里装下更多的活 |
| **模型能在你电脑上做什么** | — | 在桥接允许的范围内，直接执行命令或读文件 | 什么都不能直接做。它只能往一个 Drive 文件夹里写文件；你本机的 agent 读它的请求、自己判断，只跑它认为合适的东西；工具从不执行请求里写的命令 |
| **主要风险** | 封号、会话令牌泄露、非官方接口一改就坏 | 远端模型（或它读到的内容里被人埋的指令）在你的电脑上动手；暴露在外的隧道 | 你自己选择上传的内容；你授予的 Drive 访问权限；在你自己的浏览器里自动操作（只在自动发送的路线上） |

一句话：不逆向、不取凭据、不走非官方 API、不合用账号、不突破任何限额。变的只是任务怎么写，以及一条消息里装多少活。手发就是和任何人一样正常使用 ChatGPT；自动发送（Voyager CLI、浏览器 agent）是在操作你自己的浏览器，这是否符合你同意过的条款，由你自己判断（见[免责声明](#免责声明)）。

## 长任务是怎么跑起来的

- **一条消息，几个小时的活。** 网页版 Pro 按消息条数计，不按 token 计。五分钟的小问题和五小时的大活花的次数一样，所以一批活放进一个任务里。
- **70 分钟保底。** 重活以前大约 80 分钟就断，断了什么也拿不回来。所以题面要求它在真正干活满 70 分钟时先交一份完整可用的成品。之后不设上限，它照着清单接着干，每 15–20 分钟存一个带序号的阶段包。就算中途断了，最新的阶段包已经在你手里。
- **清单塞满。** 下次检查之前想让它做的事全列上，再加一份后备清单。千万别写「这一轮只做 X」：它会把这句当成交单条件，提前收工。
- **随时免费加活。** 它干着的时候，你的 agent 可以通过插话通道追加要求或新任务。它在检查点和存阶段包时会去读。这不花次数。
- **让它求助。** 需要你本机才能做的事，它写一个请求文件，然后接着干别的；你的 agent 跑完写回复。
- **子代理。** 题面要它在允许范围内尽量多派子代理，外加一个只审不做的复核子代理。我们的实测里同一时刻最多 3 个在跑。
- **对话死了，** 就用重启开场开一个新对话。新题面指向最新的阶段包，损失很小。
- **记次数。** ChatGPT 不显示还剩几次，只在用完时告诉你上限和什么时候重置。所以撞上一次上限之前，记账给的剩余次数都只是估计；撞上之后把页面上的重置时间记下来，账就和实际对上了。

## 适合与不适合

**适合：** 审一整个子系统、跨很多文件的普查、方向定论、写规格、设计测试、带推理的补丁方案、对你给的数据做分析、带可运行套件的无头实验（测试、模拟、消融）、照标杆图统一画风。

**不适合：** 要开窗、要显卡、要真机、要线上服务或密钥的事；一问一答的小问题；需要来回对话的事；你一眼就能判断的事。

## 我们看到的数据

- 作者本机单次最长约 **6 小时**；一般 **2–4 小时**很稳；极个别时候仍会在 **70 分钟**左右断。
- 一单以读代码为主、带子代理的任务，一条消息读了约 **20 万行**代码。
- 用同一套流程的群友报告过 **20 小时**的单次会话，以及**同时 7 个子代理**在跑；作者本机都没有复现过。

## 仍然会遇到的情况

- 「连接已中断，正在等待完整答复」：后台常常还在跑，看 Drive 里有没有新文件。
- 「无法加载此对话」加「再试一次」：常常是暂时的，等一会儿再点「再试一次」。
- 红条「Invalid conversation body」：通常只是显示出错；刷新页面，别点「重试」。
- 提前停下的会话，在用得多或跑得特别久时更常见。

这些情况的完整对照表和处理办法见[浏览器代发说明](skills/gptidomath/send/browser-relay.md#when-things-go-wrong)。
