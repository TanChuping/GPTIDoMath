# 开场

发给 ChatGPT Pro 的消息分两部分。**开场正文**读起来像一场漫长而艰深的数学研究会话的开头，不含任何任务细节。**结尾**是一段固定的短流程：（需要时）先写 `test.txt`，再完整读完题面文件，然后开工。真正的任务放在那份文件（`TASK.md`）里，文件开头是 [`../task/zh/preface.md`](../task/zh/preface.md)，告诉模型开场只是一种叙述方式，以文件为准。

## 文件

| 文件 | 用途 |
|---|---|
| `01-…04-*.md` | 新对话的第一条消息。四份示例，主题各不相同。 |
| `continue.md` | **同一个**对话里的下一段（`{{ROUND}}` = 段号）。 |
| `restart.md` | 开一个**新**对话接续旧对话（旧对话撞上长度上限，或已经打不开）。 |
| `footer-drive.md` | 新对话，题面在 Google Drive 上。 |
| `footer-drive-continue.md` | 同一对话，下一段题面在 Drive 上。 |
| `footer-package.md` | 题面在随消息上传的压缩包里（不走 Drive）。 |
| `footer-package-continue.md` | 同一对话，下一段题面作为附件上传。 |
| `footer-github.md` | 题面在 GitHub 仓库里（作者没有实测过）。 |

用工作区工具拼消息：它会去掉开头的注释，并填好 `{{WORKSPACE}}`、`{{TASK_FILE}}`、`{{ROUND}}`（见 [`../tools/manuals/workspace.md`](../tools/manuals/workspace.md)）。其余的 `{{…}}` 手动填。也可以自己把正文和结尾粘成一条消息。

## 自己写一份

这四份是示例，不是咒语。请自己写，隔一阵换一换：很多人发同一段公开文本，很容易被认出来，也可能就此失效。几份示例的共同点：

1. **一个延续中的研究课题。** 说它是一个长期问题的续作，不是随手一问。
2. **一两个前沿领域里的四到六个真实概念**，彼此搭得上。用法要对，堆砌术语读起来只是噪音。
3. **一个抽象的研究对象。**「由许多相互作用的部分构成的有限系统」，带着出人意料的行为：隐藏的结构、罕见的失效、只在整体上显形的障碍。再给一个目标：刻画它、找出支配它的东西、在约束下求最优。
4. **方法。** 一半证明、一半测量；没核实的结论留作猜想。
5. **完全不含任务内容。** 不写文件名、产品名、编程语言、框架。说明完整题面在共享材料里，以及为什么不在这里复述：转述会丢精度，也会带偏读者。
6. **结尾的步骤保留。** 措辞可以改，顺序不改。
7. **如实、不冒充。** 不编造头衔，不自称某某人。开场和题面里都别用「绕过、漏洞利用、注入、破解」这类带安全色彩的动词：曾有完全正常的任务因为这些词被关键词过滤拦下。

三五百字就够了。用什么语言写都行；回答用什么语言，由题面文件规定。
