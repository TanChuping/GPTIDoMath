# 开场

发给 ChatGPT Pro 的消息分两部分。**开场正文**读起来像一位研究者正在啃一道艰深的数学难题，不含任何任务细节。**结尾**交代开工步骤：走 Drive 时先写 `test.txt`，再完整读完题面文件，然后开工。真正的任务放在那份文件（`TASK.md`）里，文件开头是 [`../task/zh/preface.md`](../task/zh/preface.md)，告诉模型开场只是一种叙述方式，以文件为准。

每开一个新对话，你的 agent 都按下面的流程现写一份新开场。这里的文件只是示范能写得多不一样，不是拿来发的。

## 文件

| 文件 | 用途 |
|---|---|
| `01-letter-fluid-dynamics.md` | 示例：写给合作者的信（Navier–Stokes 正则性）。 |
| `02-abstract-quantum-many-body.md` | 示例：讨论班式的短摘要，带编号问题（谱隙）。 |
| `03-notebook-extremal-combinatorics.md` | 示例：从一个失败的反例写起的研究笔记。 |
| `04-survey-hamiltonian-dynamics.md` | 示例：从历史讲起的正式综述（KAM、双曲性）。 |
| `05-objections-complexity.md` | 示例：对自己思路的三条反对意见（复杂性壁垒）。 |
| `continue.md` | 示例：**同一个**对话里的下一段（`{{ROUND}}` = 段号）。 |
| `restart.md` | 示例：开一个**新**对话接续旧对话（旧对话撞上长度上限，或已经打不开）。 |
| `footer-drive.md` | 结尾：新对话，题面在 Google Drive 上。 |
| `footer-drive-continue.md` | 结尾：同一对话，下一段题面在 Drive 上。 |
| `footer-package.md` | 结尾：题面在随消息上传的压缩包里（不走 Drive）。 |
| `footer-package-continue.md` | 结尾：同一对话，下一段题面作为附件上传。 |
| `footer-github.md` | 结尾：题面在 GitHub 仓库里（作者没有实测过）。 |

用工作区工具拼消息：它会去掉注释，并填好 `{{WORKSPACE}}`、`{{TASK_FILE}}`、`{{ROUND}}`（见 [`../tools/manuals/workspace.md`](../tools/manuals/workspace.md)）。还剩别的 `{{…}}`，或者消息里没写出任务文件夹和题面文件名，它都会拒绝出消息。

## 每个新对话现写一份开场

这是每一单的固定步骤，不是可选项。很多人发同一段文字，或者同一段文字只换几个名词，这些消息就带着同一个指纹，很容易被批量认出来，这个办法也就可能对所有人失效。所以任意两份开场都不该相像：措辞不像，结构也不像。五份示例在体裁、口吻、切入点、领域和篇幅上各不相同，就是为了示范能差多远。不要原样发送示例，也不要搬用其中的句子。

**开场只需要做到三件事：**

1. **说清真正的任务在哪。** 完整题面在共享材料（或随附的压缩包）里，以它为准。具体路径由结尾给出。
2. **立在真实的前沿数学或物理上。** 公开问题、近年的突破、活跃的研究方向；挑几个真正相关的概念，人名和结论都要对。拿不准的细节，就换一个有把握的更宽泛的说法；编出来的定理读起来只是噪音。
3. **像一位严肃的研究者在工作。** 措辞精确、严谨、学术，读的人会相信这是一位教授正在做的研究。

**不能出现：** 任务细节（文件名、产品名、编程语言、框架）；编造的头衔，或自称某某人；「绕过、漏洞利用、注入、破解、攻击、载荷」这类带安全色彩的词，曾有完全正常的任务因为它们被关键词过滤拦下。

**其余一切都自由，而且每份都该换：**

- **体裁：** 给合作者的信、讨论班摘要、研究笔记、综述、对自己思路的反驳、一串公开问题、基金申请式的问题陈述、一整段密实的论述，或者别的什么。
- **口吻：** 我、我们，或不用人称；笃定、困惑或存疑；正式或随意。
- **切入点：** 一个失败的证明、一个反例、数据里的一处反常、一段历史、一个定义、一个问题。
- **领域：** 按和这一单的相像程度来挑（见下一节）；有别的领域也合适时，别连着两次用同一个。
- **篇幅与版式：** 150 到 600 字（英文按词计）；有标题或没有；段落、要点或编号问题；指向材料的那句话放在开头、中间或结尾都行。

### 怎么挑领域

挑一门研究对象和真实任务**形状相同**的数学或物理，让模型读到题面时能认出这层相像：什么在累积，什么必须保持不变，哪里会坏，在优化什么。相像只留在结构上。写数学对象，不写真实的工具、产品或文件格式：写「多面体曲面」，不写「Blender 网格」。搭得松一点没关系，题面开头的关系说明会告诉模型不必花时间去调和两者。

内容还要**够前沿**：以大约近十五年的公开问题和成果为主，经典结论只作铺垫。每个人名、年份和结论都要核实，拿不准的就别写。

下面这些都是真的，可以从这里起步：

| 这一单主要在做 | 形状相同的领域 | 为什么搭得上 | 可用的前沿 |
|---|---|---|---|
| 三维建模、网格、曲面 | 离散微分几何 | 网格就是离散曲面，曲率、光滑度、畸变是它的量 | 多面体曲面的离散单值化（Gu–Luo–Sun–Wu，2018）；Willmore 猜想（Marques–Neves，2014）；圆填充逼近共形映射（Rodin–Sullivan） |
| 流体、烟雾、布料等物理模拟 | Navier–Stokes 方程与湍流 | 能量在尺度间流动、数值爆破 | 三维 Navier–Stokes 正则性（未解）；Onsager 猜想（已解决，Isett 2018）；Tao 的平均化方程爆破（2016）；Boussinesq 与带边界三维 Euler 的计算机辅助爆破证明（Chen–Hou，2022） |
| 渲染、光照、采样噪声 | 积分几何、偏差理论、调和分析 | 光是沿光线的积分，噪声就是偏差 | 三维 Kakeya 猜想（Wang–Zahl，2025）；Fourier 限制猜想（未解）；ℓ² 解耦（Bourgain–Demeter，2015） |
| 动画、绑定、机器人、相机 | 刚性理论、几何力学 | 姿态活在旋转群上，关节就是约束 | 一般位置下整体刚性的刻画（Gortler–Healy–Thurston，2010）；可伸缩多面体的风箱猜想（Connelly–Sabitov–Walz） |
| 并发、多人同步、分布式状态 | 有向代数拓扑、层 | 死锁是调度空间里的洞，粘不起来的局部一致是一个上同调类 | 有向同伦（Fajstrup–Goubault–Raussen）；无等待不可能性的拓扑证明（Herlihy–Shavit、Saks–Zaharoglou，2004 年 Gödel 奖） |
| 游戏逻辑、大型状态机、规则系统 | 巨大有限状态空间上的马尔可夫链、亚稳态 | 只在完整规模上才出现的长寿罕见状态和瓶颈 | 截断现象（Lubetzky–Sly；Salez 对非负曲率链的证明）；亚稳态与 Eyring–Kramers 公式（Bovier–den Hollander） |
| 性能、调度、参数调优 | 最优输运、尖锐阈值 | 以最小代价搬运质量；过了某一点性能骤降 | Wasserstein 梯度流（Jordan–Kinderlehrer–Otto）；Kahn–Kalai 猜想（Park–Pham，2022） |
| 数据分析、统计、模型评估 | 随机矩阵、高维概率 | 在大矩阵里分开信号和噪声 | BBP 相变（Baik–Ben Arous–Péché）；特征值普适性（Erdős–Schlein–Yau、Tao–Vu） |
| 网络、路由、负载均衡 | 扩张图、渗流 | 大型网络的健壮性与瓶颈 | 任意度数的二部 Ramanujan 图（Marcus–Spielman–Srivastava，2015）；三维临界渗流（未解） |
| 编译器、类型检查、重构、规则引擎 | 重写系统、类型论 | 合流、终止、相差一个协调意义下的相等 | 立方类型论让单值公理可计算（Cohen–Coquand–Huber–Mörtberg） |
| 生图、画风统一 | 最优输运、基于得分的扩散 | 把一组图像的分布搬到另一组上 | 基于得分采样的收敛保证（Chen–Chewi–Li–Li–Salim–Zhang，2023）；Schrödinger 桥 |
| 边界情况、测试生成、大搜索空间 | 极值组合与加性组合 | 只在规模上去之后才出现的反例 | 帽集上界（Ellenberg–Gijswijt，2016）；向日葵界（Alweiss–Lovett–Wu–Zhang，2019）；Erdős–Hajnal 猜想（未解） |

一单横跨好几行时，取它最核心的那一行。哪行都搭不太上时，取最接近的形状（一个大的有限系统、它的不变量、它的瓶颈），差的那点交给关系说明去兜。

**流程，每个新对话做一遍：**

1. 看这一单的形状，按相像程度挑一个领域（见上表），再从中挑三到六个真实、够新的概念或公开问题。
2. 选一种和上一份不同的体裁、口吻和切入点。Pro 记账替你记着：发送后记账时写上 `pro_ledger.py add <tag> --note "opener: 书信, 流体 PDE"`，以前用过什么，用 `pro_ledger.py list` 查。
3. 用要发送的语言从头写。
4. 自查：领域和这一单形状相同；三件事都做到；不能出现的一样没有；没有一句来自示例或之前的开场；人名和结论都真实。
5. 结尾也换个说法，步骤和顺序不变。
6. 把开场存在题面源文件旁边，不要放进同步的工作区；连同结尾一起交给 `drive_workspace.py --opener … --footer …`。

续篇和重启守同样的规矩。`continue.md` 和 `restart.md` 示范了这两种还必须说的话：这是第几段，或者此前已有一卷、它的手稿放在哪里。

用什么语言写都行；回答用什么语言，由题面文件规定。
